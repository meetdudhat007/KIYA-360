# KIYA 360 — Requirement Status Legend

Requirement **status** describes the maturity of a detailed requirement. It is separate from requirement **classification** (BRD-REQUIRED, BRD-DERIVED, PROPOSED, TBD, OUT-OF-SCOPE).

Clarification-decision status is a third, separate control. The `CD-###` lifecycle in `16-clarification-decision-register.md` governs whether a clarification is authoritative; this document governs the requirement itself. An approved CD may authorize a requirement update, but it does not automatically approve the affected requirement. A non-approved CD must not be used to advance a requirement status.

| Status | When it may be used |
| --- | --- |
| Not Started | The Phase 0A record has not yet entered detailed analysis. |
| In Analysis | Evidence, dependencies, and open questions are being examined; no review-ready draft exists. |
| Draft | A detailed requirement has been written but has not completed review. |
| Needs Clarification | Material detail is missing or conflicting; a linked TBD/open question requires a decision. |
| Reviewed | Review occurred and feedback is incorporated or recorded; approval is still pending. |
| Approved | The detailed requirement and its evidence/decision record have been formally accepted by the appropriate authority. |
| Superseded | Replaced by an approved requirement or approved change record; retain reference to the successor. |

Do not use a status to imply an unapproved decision. A BRD-REQUIRED requirement can be Not Started, and a Draft requirement can still contain TBDs.
