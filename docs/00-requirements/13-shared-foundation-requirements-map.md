# KIYA 360 — Shared Foundation Requirements Map

## 1. Purpose

Shared foundations must be identified before module-by-module specification so that detailed requirements do not conflict over common enterprise context, masters, controls, flow enablers, or platform-wide capabilities.

## 2. Definition of Shared Foundation

A shared foundation is a requirement/capability explicitly applicable to multiple modules, explicitly identified by the BRD as common/shared, or clearly required by multiple BRD-defined flows. It is not labelled shared merely because it is common in ERP products.

## 4. Coverage Notes

All 28 modules were considered. Modules without a separately named foundation record participate through the explicitly all-module foundations (SF-001, SF-002, SF-003, SF-005–SF-008, SF-011, SF-012, SF-014, SF-015) or their BRD-defined flow/cross-module links. No database schema, API, UI, technology, workflow condition, approval limit, or notification trigger is defined here.

## 5. Traceability

Each `SF-*` ID is an analysis identifier, not a BRD requirement ID. Its evidence links to the current BRD and the cited Phase 0A requirement records in `05-requirement-traceability.md`.
